# Aggle Phase 1 — Full Implementation Plan## Architecture OverviewThe extension follows a **modular message-passing architecture**: the **background script** (`background.ts`) is the central coordinator. All features communicate via `browser.runtime.sendMessage` / `browser.runtime.onMessage` with typed messages. State is persisted in `browser.storage.local`. Each feature is a self-contained module.**Build changes needed:** Add new entry points to `esbuild.ext.config.mjs` for options page and blocker modules. Add two small runtime dependencies: `marked` (markdown rendering, ~40KB) and `highlight.js` (syntax highlighting, tree-shakeable).**Manifest changes needed:** Add `declarativeNetRequest` permission for ad blocking, add `activeTab` for page content extraction, register new HTML pages.---## Implementation Order (10 Batches)### Batch 1: Foundation Layer**Create shared infrastructure everything else depends on.**New files:- `src/utils/storage.ts` — Typed wrapper around `browser.storage.local` with defaults schema- `src/utils/messages.ts` — Typed message definitions (action types, payload types, response types) and a `sendMessage` helper- `src/utils/constants.ts` — Brand tokens (`#0A0A0A`, `#FF5A1F`, `#FF8A3D`), default settings, resource profile presets- `src/utils/prefs.ts` — Helper to read/write Firefox prefs via `browser.privacy` API- `src/types.ts` — Shared TypeScript interfaces (Theme, Provider, FilterList, ResourceProfile, etc.)### Batch 2: Icons + Options Page Shell**Every feature needs a settings UI.
